# Термины и сокращения

## Термины ТЗ

| Термин ТЗ разд. 1 | Как в системе |
| --- | --- |
| Workflow: «последовательный алгоритм<br>действий, автоматизированный и<br>визуализируемый в CRM-системе» | Маршрут: шаги и переходы; для вузов один, без<br>версий |
| ИТ-направление: «направление в ИТ по<br>обучению, например, DevOps, QA и т.д.» | Пять крупных категорий edu-rt.ru: Аналитика,<br>Дизайн, Информационная безопасность,<br>Разработка, Управление проектами |
| ИТ-программа: «программа, содержащая в себе<br>методические материалы и практику по тому<br>направлению, по которому она написана» | Одно направление; продуктов может не быть |
| ИТ-продукт: «ПО, помогающее в обучении по<br>одному или более ИТ-направлению в вузе» | Один вендор, минимум одно направление |

## Направление → программа → продукт → договор → ветка

Пример: Аналитика → «Аналитика данных и методы искусственного интеллекта на базе решений ПАО «Ростелеком»» → RT.DataLake и RT.Warehouse, вендор TData → договор Д-2026/017 с ТПУ → ветки 201 и 202; «Инженер-тестировщик» без продукта: ветка 203.

Договор у заявки один, продукты входят в него; ветка = программа + не больше одного продукта (см. раздел 5.4).

## Термины решения

| Термин | Что значит |
| --- | --- |
| Заявка | Работа с вузом по одному договору; у вуза одна незакрытая заявка (раздел<br>5.4) |
| Ветка | Программа + не больше одного продукта; после шага 4 идёт по шагам 5–8<br>отдельно (раздел 4.4) |
| Шаг | Этап маршрута, в ТЗ, работает как «статус». Шаги 0-4 и 4.1 считаются<br>уровень заявки, а шаги 5-8 - уровнем ветки (раздел 4.3) |
| Допсоглашение | Шаг 4.1: изменение подписанного договора для, например, расширения<br>программ сотрудничества; можно предложить одно за раз, утверждается оно<br>одобрением от руководителя. (раздел 4.4) |
| Одобрение, запрос на<br>решение | То, что решает руководитель: переход, закрытие, допсоглашение, запросы из<br>LMS (раздел 3.1) |
| Пауза / застой | Остановка заявки или ветки с комментарием и необязательным сроком,<br>застой на паузе не считается / нет движения дольше порога: общий период<br>застоя - 14 дней, руководитель может задать свой (раздел 4.4). Важное<br>различие - пауза - это контроллируемое приостановление работы, застой -<br>отсутствие прогресса заявки, находящейся в работе. |
| Ответственный КАМ | Сотрудник ИТ Школы, пользователь системы; один на заявку, назначает<br>руководитель (раздел 3.3) |
| Ответственные от вуза | Контактные лица вуза, поле ТЗ «Ответственные от ВУЗа»; не пользователи<br>системы, ПДн шифруются (раздел 5.3) |
| История заявки / журнал<br>действий | События заявки видят КАМ и руководитель, журнал всех действий видит<br>администратор; ФИО, телефон и email сотрудников и контактов в журнал не<br>пишутся (раздел 3.1) |
| Статистика LMS | Студенты, потоки, обученные преподаватели по паре «вуз × программа»<br>(раздел 5.4) |
| Запись на обучение | Запись человека на курс с сайта; вместо email - отпечаток (раздел 6.5) |

## Сокращения

API - интерфейс обмена данными; B2B / B2C - работа с вузами / с физлицами; CMS - система управления сайтом; CRM - система управления взаимоотношениями с клиентами; LMS - система управления обучением; S3 - хранилище файлов; БД - база данных; ИНН / КПП - налоговые реквизиты вуза; КАМ - менеджер по вузам; ОКСО - классификатор специальностей по образованию; ПДн - персональные данные; РТК - ПАО «Ростелеком»; 149-ФЗ - ФЗ «Об информации, информационных технологиях и о защите информации»; 152-ФЗ - ФЗ «О персональных данных»; ФСТЭК № 117 - приказ ФСТЭК России № 117.
