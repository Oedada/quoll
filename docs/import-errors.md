# Коды ошибок импорта — CRM ИТ Школы РТК

*v1.0 · 28.09.2026 · для разработчиков · основа — `docs/import-design.md` ред. 3 §22, код ветки `imports`; пути — от `backend/src/quoll/`. Формат — как в `errors-ru.md` заказчика (там этих кодов нет, старые IMP-001…007 из прежнего `interactions/import_service.py` заменяются этими).*

## 1. Как устроены коды

- Область IMP, как в общей нумерации (`errors-ru.md` §1).
- Раздел 22.1 дизайна — ответы ручек `/api/v1/imports` (HTTP-код, видит админ, категория Т - общий текст, код — в деталях ответа).
- Раздел 22.2 дизайна — замечания к строкам файла (`issues[].code` в превью и отчёте импорта), HTTP не несут. Категория — уровень: **E** ошибка (блокирует строку/группу), **C** конфликт (нужно решение админа, коммит 2), **W** предупреждение (не блокирует), **I** сведение (информация о слиянии/переносе).
- «Текст пользователю» и «Что делать» для строковых замечаний — короткое описание причины (колонка «Когда» дизайна): это внутренний инструмент админа, отдельной UI-копии дизайн не задаёт. Финальную формулировку для интерфейса пишет фронт по этим формулировкам при вёрстке (см. список отклонений в `docs/handoff/imports-status.md`).
- Параметры `{…}` — то же самое, что в `issue(code, **params)` (`imports/spec.py`): `ref_row` — номер строки файла (не БД), `field` — название поля, `candidates`/`groups`/`used`/`max` и т.п. — как в дизайне.
