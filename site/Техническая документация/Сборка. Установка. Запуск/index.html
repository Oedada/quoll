    Сборка. Установка. Запуск

    Окружение

    • Linux (Ubuntu 22.04 LTS / Debian 12 / Astra Linux SE), Docker 24+, Docker Compose v2. • Python 3.12+, менеджер пакетов uv (или pip). • Node.js 20+ (для сборки фронтенда, если требуется локальная пересборка без Docker).

    Компиляция, сборка, установка, запуск

    1. Клонирование репозитория:
    git clone https://github.com/Oedada/quoll.git
cd quoll
    1. Настройка окружения:
    cp backend/example.env backend/.env
# Отредактируйте .env, сгенерировав обязательные ключи шифрования (см. ниже)
    1. Запуск всех сервисов в Docker:
    docker compose up -d --build

    При старте поднимаются PostgreSQL 16, Keycloak 26, Garage S3, фронтенд и бэкенд FastAPI. Настройки Keycloak и демо-пользователи импортируются автоматически при старте контейнера (--import-realm, файл keycloak-start-settings.json).

    Первичная настройка

    Переменные окружения заданы в backend/example.env, копируются в .env. Обязательные перед первым запуском — SESSION_SECRET_KEY и PII_ENCRYPTION_KEY, оба генерируются одной командой:

    python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

    и намеренно оставлены пустыми в example.env. Миграции базы данных применяются автоматически при старте контейнера (alembic upgrade head). Демо-данные загружаются администратором через интерфейс импорта (demo-data.xlsx).

    Проверка, что всё работает

    1. GET / — health-check приложения, {"ok": true}.
    2. Вход под демо-учётной записью и прохождение цепочки: черновик → назначение → переход по шагам.
    3. GET /docs (Swagger UI) — документированные методы, требование 6.6.2.
    4. Healthcheck самого Keycloak в docker-compose.yml (TCP-проверка .well-known/openid-configuration). Сервис зависит от condition: service_healthy.
